# 青跳开发版（cyan-skip）

cyan-skip（中文名青跳）是基于 [GKD](https://github.com/gkd-kit/gkd) 二次开发的独立 Android 精简版，只保留规则点击与页面快照等基础功能，不做商用，并非 GKD 官方发行版。保留上游版权与 [GPL-3.0-only 许可证](../LICENSE)。

## 当前范围

- 首页：服务状态、自动匹配开关、规则概览、快照悬浮按钮。
- 规则：同页展示本地规则与订阅卡片，直接启停、查看应用/全局规则、更新和管理。加号区分自定义规则与订阅链接；自定义规则支持粘贴或选择 UTF-8 JSON/JSON5 文件。
- 快照：悬浮按钮抓取、列表、查看、导出和删除；在快照上点选位置即可生成规则并在快照上验证命中范围。
- 设置：必要权限、通知、后台隐藏、点击提示、快照选项、执行记录、主题和备份恢复。
- 外观：青色品牌主题，支持浅色与深色；首页匹配开关名称为「功能开关」。
- 后台隐藏：开启后从最近任务列表隐藏，保留桌面图标，不主动停止规则服务；关闭后恢复任务可见。实际运行仍受系统后台管理影响。
- 启用订阅不再显示耗电警告，对应设置字段已删除。
- 订阅：在规则页直接添加与管理，兼容现有规则格式，不再有「更多规则与订阅」中间页。

主导航只有首页、规则和快照。已删除高级设置、旧设置/关于页面、诊断悬浮窗与日志页面、GitHub 上传/Cookie/快照上传事务、自更新实现。手机端 HTTP 服务已删除；检查协议与 Ktor 服务端依赖仅保留在 JVM 开发宿主，不进入 APK。保留规则引擎、快照所需权限与平台能力、执行记录、备份恢复；不保留旧数据库迁移、退役字段、旧备份转换和退役页面路由。

## 不兼容旧版本

本项目只支持当前版本，不保留任何为兼容旧版本而存在的代码或逻辑：旧数据、旧数据库与迁移、旧备份、旧设置字段、旧文件布局与文件名、旧包名与应用 ID、旧深链接与路由、旧协议字段一律直接弃用，不读取、不迁移、不转换、不回退、不双写；破坏性变更需要全新数据环境，程序不自动迁移也不自动清空用户数据。Android 系统版本适配、外部规则与订阅格式解析、当前版本内部标识与全部消费者的同步修改不属于此范围。详见 [开发约束](../AGENTS.md)。

## 安装与使用

开发包应用 ID 为 `app.cyanskip.android.debug`，正式变体为 `app.cyanskip.android`，可以与上游 GKD 共存。应用名称为「青跳」。测试时请仅开启其中一个应用的自动规则执行，避免重复点击。

1. 打开首页的服务入口，按页面提示授予无障碍权限。
2. 打开「规则」，点加号，选择「导入自定义规则」，粘贴规则或选择规则文件，检查后保存，再开启本地规则卡片的开关。
3. 回到目标应用验证规则。可在设置的执行记录中查看命中情况。
4. 需要新规则时，开启快照悬浮按钮，切换到目标页面并点相机按钮抓取。
5. 回到「快照」，打开这条快照后点右上角的「生成规则」，在截图上点一下要自动点击的位置，确认效果和名称后保存；生成的规则会出现在「规则」页的本地规则里。
6. 也可以只检查和导出快照，使用 [GKD 审查工具](https://i.gkd.li/) 分析。

规则列表的文件导入用于应用/规则组对象，订阅链接从加号菜单的「添加规则订阅链接」添加，添加后直接在规则页显示。文件必须为 UTF-8，最大 2 MiB；无效内容在保存时给出错误。

快照可能包含界面文字与截图，默认在本机保存。只提供本地文件分享，已移除单条及批量快照的 GitHub 上传与链接生成入口。应用不内置规则源、不自动导入示例规则，已停用上游 APK 更新入口。

## 构建

沿用上游 Gradle 工程，使用 JDK 21、Android SDK 37 和 Build Tools 37.0.0：

```powershell
./gradlew.bat :cyanskip-app:compileKotlinJvm :cyanskip-android:assembleDebug
```

APK 输出到 `cyanskip-android/build/outputs/apk/debug/`。桌面隔离预览及 HTTP 交互验证见 [开发宿主文档](../cyanskip-app/README.md)。桌面宿主不能证明 Android 无障碍点击、悬浮按钮和实际截图正常。

## 快照点选与缩放修正（2026-10-12）

用真机快照（淘宝 `TBMainActivity`，1672×2364、470 节点）复现并修掉三个问题：

- 点底部横幅的「×」时提示「还有 6 个相似位置会被点到」：原因是同一坐标上压着信息流卡片，按下层节点面积最小取目标取到了卡片（卡片自身无文字/编号，`[depth][index]` 一类条件命中 7 处）。现在按绘制层级（同层序号靠后者在上、后代在上）取上层节点，选中横幅本体；同时生成器会试遍祖先与相邻节点的每个特征，并用「可点击」这种弱特征描述目标本身，得到唯一且带编号的条件 `[vid="homepage_pop_view"] [clickable=true]`（快照上命中 1 处）。
- 放大后高亮位置与截图错位：原因是叠加层用布局宽度推算缩放，而图片按 `FillBounds` 各自拉伸，放大后两者比例不一致。现在截图与高亮框都在同一块画布、同一套 `translate + scale` 变换里绘制，2.5 倍放大下逐个像素核对边框与图片内容仍然贴合。
- 缩放手感：改为相机模型（视口中心对应的截图坐标 + 相对完整显示的倍数），双指缩放围绕手指、单指拖动跟手、双击放大或还原、按图片边界夹紧；视口变化（下方选项面板出现）不再把画面重置回完整显示，选项面板固定高度，选中前后图片区域大小不变。
- 自动化验证：新增 8 项相机测试（锚点不动、夹紧、视口变化保持缩放与中心、双击切换）与 2 项点选/生成器回归测试（重叠横幅取上层、上层容器用祖先编号定位）；`cyanskip-app:jvmTest` 全量通过。隔离桌面宿主回放同一张真机快照，点「×」得到「只点击你刚选中的这一个位置 · 识别方式：控件编号「homepage_pop_view」」，双击放大 2.5 倍后边框仍贴在横幅边缘。
